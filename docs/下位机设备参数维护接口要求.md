# 下位机设备参数维护接口要求

这是下位机开发端在其独立、获授权工程中的后续工作。本仓库不修改 `ros2_ws_car/`，也不以新增 mock 字段冒充设备接口已交付。

现有文档41只允许 startup_timeout/video_required，不支持电机ID、方向、减速比、零位、限位或设备持久参数。Qt已有管理配置事务闭环，但不能据此承诺电机维护已完成。下一批应先冻结以下契约与可执行fixture，再扩展 Qt 编辑器：

1. 现场列出最常修改的字段和受影响轴。逐字段提供稳定ID、权威源文件/生成链、JSON类型、单位、范围、依赖、只读/可编辑、默认值来源及schema版本；缺失字段必须返回未知，不能填入猜测的设备值。
2. 明确哪些是管理启动参数、ROS运行参数、受控生成文件、标定或设备非易失写入。设备持久写入须独立、显式操作，不能绑定普通候选保存或文件应用。
3. 复用现有管理连接与配置事务；冻结能力声明、方法/参数/响应、revision、请求幂等和operation持久语义。定义单档案或整包的影响范围、并发冲突与帧预算，不由 Qt 拼路径或调用任意shell。
4. 维护前提由下位机再次验证：资源归属、实际停组/零速、急停/安全域要求、无活动运动任务、有效源revision。修改方向/比例/零位/限位后使原授权失效，并要求受影响轴重新检查。
5. 定义候选校验、差异/影响、生成物校验、备份、应用、重载/重启及实际读回的状态和错误。文件激活、ROS读取、设备实际值与NVM写入分别报告，不以文件摘要代替设备生效。
6. 规定断电/崩溃/超时后如何按原operation查询、确认实际状态及受控恢复。明确文件回滚和设备不可逆写入的边界，未知结果不得自动重放。
7. 交付无设备正常/失败/冲突/并发/接受响应丢失/激活中崩溃/读回不一致/回滚失败fixture、匹配构建标识、部署说明及真实设备验收步骤。Qt端据此实现schema驱动字段、维护门槛、原ID恢复及差异/生效显示。

当前Qt没有以上设备字段的写入入口。文档39/40/41已交付的启停、控制v2和管理策略事务不重复实施；系统自启、真实ROS健康、CAN、视频及设备输出由部署与实机验收分别签收。
