# Qt 控制 v2 与诊断使用

日期：2026-11-08。上位机构建标识 `host-ros2-v2-config-2`，匹配下位机文档40/41、参考构建系列 `robot24-p0-config-2`。管理连接仍为 v1；运动、授权和生命周期操作使用控制 v2。兼容声明见 [compatibility.json](../deploy/compatibility.json)。

## 连接与授权

1. 优先通过“运行管理 / 启动系统”连接管理服务。软件就绪、档案匹配且必需模块健康后，Qt 取得机器人身份及控制 v2 端点，再连接控制桥。手动 TCP 对话框也必须填写机器人身份，默认 `robot24`。
2. Qt 核对机器人身份、六项必需能力、session 与 epoch。管理端点非 v2、身份不符或能力缺失会阻止连接；生产界面不自动降级到旧运动协议。
3. 松开键盘、手柄按钮并让摇杆归中，等待新鲜中立输入被确认。连接后默认无两类授权。状态栏分别显示通信阶段、操作授权、遥控授权、实际运行许可和桥接急停。
4. 点击“允许操作”后才提交 init/enable/disable/halt/resume/recover/shutdown、模式切换和命名目标请求。执行顺序及许可最终由下位机核查；仅软件 ready 不代表已初始化、已使能或可运动。
5. 实际运行许可已确认且未急停时，点击“允许遥控”。运动授权与操作授权独立；命名目标运动需要两者及实际运行许可。按键和按钮中的旧模式、速度、服务切换边沿不会作为连续输入发出。离散功能使用现有业务按钮；未列入 v2 的旧原始关节、电机、笛卡尔写入口拒绝发送。
6. 暂停遥控或撤销操作授权会重建未授权会话。连接恢复、epoch变化、令牌/实际状态过期、输入拒收、急停以及需重新核对的操作结果都会撤权，恢复后必须重新中立与明确授权。应用失去前台活动状态时也暂停控制。

中立检查依据实际采样。暂停时发送的合成零值不能证明物理中立；重连/急停清理时仍按住的键，必须收到释放事件才解除等待。窗口失去焦点导致释放事件缺失时，回到应用后按下并释放相应按键，重新核对中立；不能用清空显示绕过检查。

## 输入、急停和任务

每100ms请求 freshness token，按请求发送时刻扣除往返时间，最长300ms有效；每次新token要求重新采样，不为旧输入补新token。持续输入只有一个在途帧，最多32个协议请求；本地超时使用单调时钟。实际许可每200ms查询，500ms未更新视为过期，持续失效重建会话。运行许可未知时无法授权运动。心跳仍用于独立的双向链路观测，不刷新运动 watchdog。

急停使用单独的短连接，绕开普通控制连接和队列，2秒内等待匹配响应。已有目标地址时，即使普通连接已断开也可尝试发送。界面区分“桥接急停已锁存”和“物理停止未确认”；ACK不证明实际电机已经停止。明确解除急停后，两类授权仍保持撤销。

生命周期与模式请求用持久 request_id 和原参数记录，再发送。accepted/running只表示接受/执行中；每500ms查询任务，只有非invalidated的succeeded业务结果用于界面更新，模式切换随后同步实际桥接模式。invalidated、迟到接受响应和结果未知均不得恢复授权。

操作接受响应丢失时不自动重发。在“控制与遥测诊断”选择请求，点击“查询/恢复所选请求”并核对确认：有operation_id时只查询；未知是否接受时，以原ID及原参数恢复，服务端若尚未接受，可能执行该操作。若需新操作授权，先中立并明确授权。未知结果未核对前阻止新业务操作，halt/disable/shutdown及独立急停仍可使用其相应许可路径。

最多保留64条恢复记录、最多16个在执行操作；满时只淘汰已完成记录，保留未知意图。记录按控制端点和机器人隔离，位于 `QSettings("HostComputer", "ControlV2")`，不保存token/session。记录损坏或写盘失败时阻止新业务操作并保留证据，先离线核查，不能直接删除后假定旧操作没有执行。

## 遥测与诊断导出

工具栏打开“控制与遥测诊断”，查看构建、会话阶段、epoch、两类授权、实际许可、拒收计数、队列深度、任务、输入/状态年龄、心跳及freshness RTT。状态仓库将CO₂、IMU、关节与控制状态按各自时限标记过期，断线失效；姿态保留最后观测图形并显示过期提示，不填造零姿态。

“导出诊断 JSON”原子保存最近256条事件、最近512个freshness RTT样本的p50/p99、最新遥测和控制状态。本地观测使用单调年龄，日志时间为UTC；session/token、密码和带认证信息的URL已脱敏。导出拒绝写入本仓库下位机参考目录。它不包含完整管理服务日志、ROS2追踪或硬件反馈，需现场另行采集。

## 验证与发布

独立回归、只读参考契约命令见 [通信测试说明](../tests/communication/README.md)。全部运行在无设备环境；输出归零断言针对注入的模拟输出，不是实机验收。

构建后可检查本地版本、动态库和FFmpeg，并产生带SHA256的证据：

```sh
/tmp/hostcomputer-qt6-build/hostcomputer --version
python3 -B scripts/check_host_release.py \
  --binary /tmp/hostcomputer-qt6-build/hostcomputer \
  --output /tmp/hostcomputer-release-check.json
```

该检查不启动GUI、不部署下位机。Qt平台插件、QML/Quick3D、SDL手柄及FFmpeg打包需在干净目标系统验收；Windows须用匹配Qt6工具链构建并运行windeployqt（包含resources/qml）、部署SDL/FFmpeg后复测。当前Linux本机构建不能作为Windows验证或干净机器发布验收。

现场还须按计划核查物理断网/半开、跨机器时钟跳变、实际runtime许可与输出归零、ROS2与视频隔离、systemd冷启动。100轮程序主动断开/重连只证明该软件场景，不能替代100轮物理断网。
