# Qt 控制 v2 与诊断

更新：2026-11-17。上位机 `host-ros2-v2-field-1`，管理 v1、控制 v2。目标现场控制扩展构建为 `robot24-field-control-2`；实际身份、版本和能力以连接响应及 [兼容声明](../deploy/compatibility.json) 为准。此页合并原三组预设、实车控制和诊断操作说明。

顶部“输入方式”默认键盘，可切换手柄；切换会暂停遥控。来源过滤只影响运动帧，中立检查仍使用两类物理输入。键盘捕获、当前按键反馈与编辑时暂停见 [手柄键盘说明](手柄键盘控制说明.md)。

## 连接、选择与授权

优先从 [一键启动](上下位机启动与控制说明.md) 连接管理服务；手动 TCP 入口也必须填写实际机器人身份。客户端核对六项基础能力、session、epoch 和 freshness，不静默降级为旧运动协议。

| 能力 | 用途 | 缺失时 |
| --- | --- | --- |
| `motion_presets_v1` | 选择和控制运动组 | 禁止分组启动，不回退为全车启动 |
| `speed_level_v1` | 显式五档换档 | 禁用换档 |
| `latched_global_stop_v1` | 独立全局禁止与分步恢复 | 禁用相应恢复流程；不能宣称具备该保障 |

连接后默认没有操作授权或遥控授权。释放键盘和手柄按钮、摇杆与扳机归中，并等待新的物理中立输入确认，再明确授权。两种授权相互独立；实际运行许可也必须由下位机确认。窗口失去活动焦点、断线、epoch 变化、token/状态过期、急停及相关输入拒收都会暂停控制，恢复后需要重新归中和授权。

暂停时的合成零输入不证明物理中立。清理时仍按住的键必须收到释放事件；丢失释放事件时，回到应用后重新按下并释放相应键。手柄热插拔本身不额外撤销已有授权，其他安全门槛照常检查。

## 三组运动预设

| 预设 | ID | 底层组 |
| --- | --- | --- |
| 摆臂 | `flippers` | flippers |
| 底盘 | `base` | base |
| 机械臂（含夹爪） | `arm` | arm、gripper |

支持七种非空组合；全车是三个全选。当前现场只接底盘，应只选底盘。运行环境 hardware/mock 决定实机或模拟，预设决定运动范围，vehicle/arm 模式决定输入映射，三者不同。

“一键启动”按实际状态执行 `init → enable → resume`，每步等待任务终态、新鲜运行状态、当前 epoch/token、中立输入和所需授权。Running 组跳过重复初始化/使能；Fault 需要操作员显式恢复。流程最后在组合许可成立时申请遥控授权。机械臂的 arm/gripper 都达到目标状态才视为该预设成功，部分失败不表示其他组已经停止。

- 增加组：勾选新组合并点击“一键启动”，提交新选择、撤销旧授权，再启动需要改变状态的组。
- 减少组：调整勾选后点击“一键启动”，流程先停止移除组并等待新鲜停止证据，再提交新组合并重新授权。取消勾选本身不会停止组。
- “停止所选组”使用 halt；“更多控制”中的停止全部入口作用于服务端已确认的组，与待选勾选不同。普通停止不表示设备断电。
- “更多控制”中的“仅提交选择”不初始化或运行，移除组仍需满足停止证据；故障恢复入口需要归中和操作授权，恢复后还需明确启动。
- 启动期间普通停止会取消尚未发送的启动步骤，已受理操作仍需等结果再停止。独立急停始终覆盖全车。

下位机是否采用独立分组 v2 策略，以实际部署为准。该策略不因未选组未启动或普通轴故障直接阻断健康组；当前组的共享后端故障、全局禁止及已配置的物理联锁仍有效。多组组合仍要求组合许可完整。没有真实联锁证据时不能通过界面补成满足，也不能重新加入已删除的临时 `mock_safe_posture` 字段。

机械臂连续遥控还要求下位机部署 `enable_servo=true` 并成功切换 arm 模式；此字段不能在在线配置维护里编辑。未选 arm 时不开放 arm 模式和命名目标运动。

## 换档

在“一键启动 → 更多控制”选择 1–5 档，归中后点击换档。客户端先暂停遥控、更新状态/token、等待新中立确认和操作授权，再提交 `set_speed_level`。五秒内发送前提未满足会取消准备；已经提交的操作继续按原 ID 查询。

只有任务成功且随后 `control_status.speed_level` 与目标一致，才确认实际换档成功。选择框是目标，旁边的“当前档位”才是读回值。各档速度以服务端 `speed_control` 为准，不使用历史文档中的固定速度。`invalidated:true` 仍需同步 epoch，不表示底层没有执行。换档后需归中并明确重新允许遥控。

## 急停及恢复

空格、手柄 `L3+R3` 或急停按钮通过独立短 TCP 连接发送 `emergency_stop`，不等待普通操作或操作授权。已有目标地址时，普通连接断开仍可尝试独立急停；本地急停意图跨重连保持。

分别核对：桥接 `emergency_active` 锁存、`global_stop` 独立禁止结果、`safety_halt` 普通清理结果、新鲜 `runtime_global_inhibit` 及 `global_stop_reset_ready`。RPC 成功、零速命令和软件许可撤销均不证明机械停止。状态未同步时显示未知，不显示成已确认锁存。

原因已处理、输入归中后，在“处理急停”中按顺序操作：

1. 等待独立全局停止 `succeeded/ok:true`、运行反馈新鲜、全局禁止为 true、停止清理完成且未决操作已核对。
2. 点击“1. 解除急停锁存”并确认。发送顶层 `clear_emergency`，无需先申请操作授权；只清桥接锁存，保留 C++ 全局禁止。
3. 点击“2. 允许恢复操作”，重新取得操作授权。
4. 点击“3. 复位全局禁止”并确认，提交空参数 `reset_global_stop`。等待终态和新鲜 `runtime_global_inhibit:false`。
5. 按实际组状态显式恢复/启动，再重新归中并允许遥控。

按钮禁用时查看恢复提示和运行日志。`GLOBAL_STOP_UNCONFIRMED`、`RUNTIME_NOT_SETTLED`、反馈过期或结果未知均需先排查，不自动重试复位。停止系统、重启和重连不解除锁存，不恢复旧输入。

## 未知操作与诊断

业务操作先持久保存 request_id 和原参数，再发送；accepted/running 只表示受理或执行中。超时、迟到响应和 invalidated 不恢复授权，也不创建新 ID 自动重发。

在“控制与遥测诊断”选择原请求并“查询/恢复所选请求”：有 operation_id 时只查询；接受响应丢失时，经确认用原 ID 和原参数恢复，后端若尚未接受，可能实际执行该操作。不能把此入口当作纯只读查询。

确实无法确定结果时，先停止历史操作涉及的全部组，等新鲜停止状态和底层诊断，查询后再点击“确认停止状态并解除未知阻断”。范围缺失时要求全车停止；在途任务或过期证据不能确认。此操作只解除本地阻断，原记录仍为 result_unknown，不重放、不恢复运动；后续结果变化会再次阻断。

控制记录按端点和机器人隔离，保存在 `QSettings("HostComputer", "ControlV2")`；不保存 session/token。持久化损坏或失败会阻止新业务操作，不应直接删除记录假定操作未执行。

诊断页展示状态年龄、两类授权、许可、epoch、拒收原因、任务与 RTT，并可原子导出 JSON。导出含最近 256 条事件、512 个 freshness RTT 样本统计和最新遥测，凭据脱敏，拒绝写入只读参考目录。遥测过期保留最后观测并标记过期，不填造正常状态。

客户端通常每 200 ms 查询控制状态，500 ms 未更新视为过期；freshness 刷新按服务端声明，默认 100 ms，token/输入最长 300 ms。持续输入保持至多一个在途帧，使用单调时间判断超时；心跳不能替代输入 watchdog。输入映射见 [手柄键盘说明](手柄键盘控制说明.md)，运行日志见 [运行管理](Qt运行管理使用与联调.md)。

回归入口见 [通信测试](../tests/communication/README.md)。真实机械停止、断网输出归零、CAN 故障、部署冷启动与现场联调仍须单独验收，不能由独立 mock 或安装栈模拟替代。
