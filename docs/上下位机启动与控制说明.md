# 上下位机启动与控制说明

更新：2026-11-17。**默认上位机和下位机运行在同一台主机。** 两台主机的连接方式仅见最后一节。

## 开始前

下文约定两个工程位于当前用户的家目录：

```text
~/hostcomputer/                 上位机
~/ros2_ws_car/                  下位机
```

`~` 自动代表当前用户的家目录，不需要填写用户名。目录放在其他位置时，仍保持两个工程同级，只修改各段命令中的 `cd` 路径；后面的命令保持不变。下位机的 `linked-runtime` 和安装环境须已完成本机部署；换机时不能照搬旧配置中其他用户的路径。

每次只保留一个管理服务和一个上位机窗口。若管理服务已经运行，直接打开上位机，不重复执行管理启动命令。切换场景前先按第五节停止系统。

## 一、不接任何电机：同机模拟

**终端 1：启动下位机管理服务，保持终端打开。**

```bash
cd ~/ros2_ws_car
bash linked-runtime/run_manager.sh
```

**终端 2：启动上位机。**

```bash
cd ~/hostcomputer
bash scripts/run_linked.sh
```

**界面操作顺序：**

1. 打开“一键启动”，点击“连接”；地址为 `127.0.0.1`，管理端口默认 `9091`，令牌自动预填。
2. 在“连接设置”选择 **`mock / 模拟`**，运动组全选，点击“检查连接与环境”。
3. 检查通过后，释放按键、手柄归中，点击“一键启动”。
4. 等待组启动完成、运行许可有效；顶部选择“键盘”，点击“返回键盘控制”，需要时点击“允许遥控”。

此场景只运行模拟软件，不驱动真实电机。

## 二、只接一个控制组：同机实机

**前提：** 下位机已部署 `hardware / 实机` 档案，该组设备、接口和参数已核验。当前底盘接口按 `can0` 配置；选择底盘时只接底盘、只勾选底盘。机械臂组包含夹爪。

**终端 1：检查底盘接口，再启动管理服务。**

```bash
cd ~/ros2_ws_car
ip -details link show can0
bash linked-runtime/run_manager.sh
```

上面接口检查针对底盘；其他组改为实际接口。接口应已按现场波特率配置并启用，本说明不猜测波特率，也不自动重配总线。

**终端 2：启动上位机。**

```bash
cd ~/hostcomputer
bash scripts/run_linked.sh
```

**界面操作顺序：**

1. 点击“连接”，仍使用 `127.0.0.1`、管理端口和自动预填的令牌。
2. 在“连接设置”选择 **`hardware / 实机`**，只勾选实际接入的那个组，点击“检查连接与环境”。
3. 预检通过、输入归中后，点击“一键启动”；等待所选组初始化、使能和运行完成。
4. 确认许可有效，选择键盘或手柄并允许遥控，再进行小幅控制。

**若环境列表只有 mock，此场景暂不能执行。** 需要先由下位机部署端补齐实机档案及设备映射；连接到本机不等于使用模拟，选择 mock 也不会驱动已接入的真实电机。当前已检查的部署只有 mock，`can0` 实机映射尚未确认生效。具体部署缺口见 [底盘实机部署要求](下位机设备参数维护接口要求.md)。

## 三、接入全车：同机实机

**前提：** 全车设备、CAN 接口、实机档案和参数基线均已核验。

**终端 1：启动下位机管理服务。**

```bash
cd ~/ros2_ws_car
bash linked-runtime/run_manager.sh
```

**终端 2：启动上位机。**

```bash
cd ~/hostcomputer
bash scripts/run_linked.sh
```

**界面操作顺序：**

1. “连接” → “连接设置” → 选择 **`hardware / 实机`**。
2. 选择“全车组”，或全选摆臂、底盘、机械臂，点击“检查连接与环境”。
3. 预检通过、输入归中后“一键启动”，等待各组运行状态和许可确认，再允许遥控。

任何组未准备好或启动失败时，查看失败原因，不把软件已连接当成全车已允许运动。

## 四、查看同机连接参数（需要时使用）

管理服务启动后，另开终端：

```bash
cd ~/hostcomputer
python3 -B scripts/show_manager_connection.py --local \
  --config ../ros2_ws_car/linked-runtime/manager.json
```

脚本显示本机连接地址、管理端口、认证令牌和监听状态。只读，不修改配置；分享输出时加 `--hide-token`。管理端口默认 `9091`，控制桥默认 `9090`，连接设置填写管理端口。

配置中的相对 `token_file`（例如 `manager.token`）按 `manager.json` 所在目录解析，不受终端当前目录影响。通过 `bash scripts/run_linked.sh` 启动上位机才会加载此配置并预填令牌；直接运行程序不会自动加载。若令牌为空，先用上述查询命令确认配置和令牌可读，再关闭旧上位机窗口、用脚本重新打开。

## 五、控制、停止和急停恢复

- **键盘：** 顶部“输入方式”选键盘，点击“聚焦键盘”；底盘 W/S 前后、A/D 转向，空格急停，侧栏显示“输入方式：键盘”、接收状态和当前按键，键盘模式不显示手柄连接按钮。
- **手柄：** “输入方式”选手柄，再连接手柄。切换输入、编辑参数或失焦后需归中并重新授权。
- **正常停止：** 松开输入 → “停止所选组”（全车时停止全部已确认组）→ “停止系统”并等待完成 → 关闭上位机。需要退出管理服务时，最后回终端 1 按 `Ctrl+C`。
- **急停恢复：** 处理原因并归中 → “处理急停” → “解除急停锁存” → “允许恢复操作” → “复位全局禁止” → 重新启动所选组。按钮禁用时查提示，不删除持久状态绕过锁存。

小屏或高缩放下可使用面板和工作区的滚动条。详细输入和诊断见 [手柄键盘说明](手柄键盘控制说明.md)、[控制与诊断](Qt控制v2与诊断使用.md)。

## 六、上位机和下位机不在同一台主机

**下位机终端 1：启动管理服务。**

```bash
cd ~/ros2_ws_car
bash linked-runtime/run_manager.sh
```

**下位机终端 2：查询地址、端口和令牌。**（此处不加 `--local`。）

```bash
cd ~/hostcomputer
python3 -B scripts/show_manager_connection.py \
  --config ../ros2_ws_car/linked-runtime/manager.json
```

下位机若没有上位机工程，只需复制 `show_manager_connection.py` 一个文件；在脚本所在目录运行，并用 `--config "$HOME/ros2_ws_car/linked-runtime/manager.json"` 指定配置。

**上位机终端：** 把 `下位机IP` 换成上一步与本机网络互通的网卡地址。

```bash
cd ~/hostcomputer
bash scripts/run_linked.sh --vehicle 下位机IP
```

在“连接设置”填写查询到的管理端口和令牌，点击“连接”；之后按前面对应场景选择 mock/hardware 和运动组。`--vehicle` 只选择远端地址，不切换实机模式。

本套部署已配置管理服务、控制桥监听 `0.0.0.0`（所有 IPv4 网卡），修改需重新启动对应服务才生效。其他部署也须允许非回环监听，并确认网络及防火墙可达；连接框不能填 `0.0.0.0`。跨主机使用实际 IP，同机继续使用 `127.0.0.1`。`ROS_LOCALHOST_ONLY=1` 可保留，内部 ROS2 仍在下位机运行，不影响 TCP 远程连接。
