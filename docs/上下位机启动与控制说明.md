# 上下位机启动与控制说明

更新日期：2026-11-14。适用本机 `/home/fire/hostcomputer` 上位机和 `/home/fire/ros2_ws_car` 下位机工程。

## 先看这里

日常顺序：**下位机启动管理服务 → 上位机打开程序并连接 → 选择运行环境及运动组 → 一键启动 → 确认运行许可 → 控制 → 停止所选组 → 停止系统。**

当前已经编译、配置并验证的是本机 Mock 模拟联动。现有 `linked-runtime` 只有 `mock` 档案，版本以连接后的服务返回为准，不会驱动真实电机。要控制实车，必须另行完成下面的实机部署；不能只把界面名称改成“实机”，也不能把模拟验证当作实车已就绪。

## 一、当前电脑可以直接使用的启动方法

### 1. 下位机：先检查管理服务是否已运行

打开终端执行：

```bash
ss -ltn 'sport = :9091'
```

如果有 LISTEN，说明端口已有服务；正常情况下可直接去上位机连接。若连接失败，再核查具体进程，不要重复启动第二个管理服务。

如果没有监听，执行：

```bash
bash /home/fire/ros2_ws_car/linked-runtime/run_manager.sh
```

此终端需要保持打开。管理服务启动时不会自动使能电机，也不会自动运行运动组。ROS 整车软件和控制桥由后续“一键启动”统一拉起，**不要再手动启动另一份 `ros2 launch` 或 bridge**。

本机现有目录：

| 用途 | 路径 |
| --- | --- |
| 下位机已编译安装产物 | `/home/fire/ros2_ws_car/linked-install` |
| 管理服务配置 | `/home/fire/ros2_ws_car/linked-runtime/manager.json` |
| 模拟运行档案 | `/home/fire/ros2_ws_car/linked-runtime/profiles/mock.json` |
| 认证令牌文件 | `/home/fire/ros2_ws_car/linked-runtime/manager.token` |
| 管理服务与控制持久状态 | `/home/fire/ros2_ws_car/linked-runtime/state` |

### 2. 上位机：打开新编译的程序

在桌面图形环境另开终端：

```bash
bash /home/fire/hostcomputer/scripts/run_linked.sh
```

先关闭旧版本窗口，避免多个控制端同时占用机器人。此入口会预填本机管理配置和令牌，但不会自动连接或启动。

### 3. 在上位机连接并启动

1. 点击工具栏“系统管理”中的“一键启动”，打开右侧启动页。
2. 打开“连接设置”，确认下位机地址 `127.0.0.1`、管理端口 `9091`。本机脚本已预填令牌；通常不用重新输入。
3. 点击启动页“连接”。连接成功后，在连接设置选择服务返回的运行环境 `mock/模拟`，并点击“检查连接与环境”，确认预检通过。
4. 选择运动预设：底盘组、机械臂组、全车组、底盘和摆臂组。机械臂组包含夹爪；也可以在启动页直接勾选。
5. 释放所有控制按键、手柄按钮，将摇杆归中。返回启动页，点击“一键启动”，等待所选组完成启动并显示“运行中”。
6. 软件启动完成后，程序会使用管理服务返回的控制地址自动连接控制桥，不需要再手动连接另一份控制桥。

“软件已就绪”只表示软件可以服务；运动组还必须启动成功并获得遥控授权。如果遥控处于暂停状态，保持归中，点击主窗口底部“允许遥控”，再进行控制。不要在启动过程中按住运动键。

## 二、要控制真实机器人时，怎样启动

### 1. 首次部署需要先准备的内容

这部分只在首次部署或更换硬件/软件版本时处理；本说明没有替你执行实车部署。

- 下位机需要 ROS2 Humble 和完整安装产物。当前这台开发机已有 `linked-install`，但另一台下位机不能直接假定存在同样路径；应部署完整构建及依赖，再配置实际 `setup.bash`。
- 需要经现场核验的电机身份、方向、参数及 commissioning 基线。源码 `robot_hardware/config/commissioning.yaml` 目前是 `commissioned: false` 的模板，不能直接当作已完成登记的实机基线，也不能只改成 true 来绕过检查。
- CAN 接口名称、接线和波特率要与实际设备及配置一致。当前默认名称为 `canable0`、`canable1`。
- 需要实机 `hardware` 档案。现有模拟档案不能用于实车；真实档案不能启用 `mock_safe_posture`。
- 上下位机分两台电脑时，使用可互通的可信局域网，下位机公布上位机能够访问的实际 IP。

源码部署说明：`/home/fire/ros2_ws_car/src/robot_manager/README.md`。

### 2. 下位机的实机配置关系

例如采用正式部署目录时：

| 配置项 | 示例与要求 |
| --- | --- |
| manager 配置 | `/etc/robot24/manager.json` |
| `setup` | `/opt/robot24/install/setup.bash`，指向实际完整安装环境 |
| `config_root` | `/etc/robot24/profiles` |
| `state_dir` | `/var/lib/robot24-manager`，管理服务运行用户可写，跨重启保留 |
| `token_file` | `/etc/robot24/manager.token`，至少 32 字符，文件权限 0600 |
| `build_manifest` | `/opt/robot24/release.json`，与真实部署文件匹配 |
| `bind`、`bridge_bind` | 跨机器连接时可设 `0.0.0.0`，并确认 `network_policy_confirmed: true` |
| `control_endpoint` | `host` 为下位机实际 IP，`port: 9090`，`protocol_version: 2` |

`hardware.json` 可参考 `/home/fire/ros2_ws_car/src/robot_manager/config/hardware.json`，需要按现场修改：

- `mode` 为 `hardware`；`profile_id` 可用 `hardware`。
- `baseline` 指向 `config_root` 内实际已核验的 commissioning YAML。
- `devices` 填实际 CAN 接口，同时用 `group_devices` 明确每组使用的设备。当前硬件示例已配置底盘/夹爪使用 canable1，摆臂使用 canable0，机械臂使用两个接口；上位机传递选组后只预检所需设备。旧档案未设置映射时仍检查全部 devices。
- 档案、manager 和发布清单的 `build_version` 必须一致。源码示例的 `robot24-release-1` 不能直接混用本机产物的 `robot24-field-control-2`。
- 机械臂遥控需启用 `enable_servo: true`；这只加载软件，不会自动使能电机。
- 无视频可用 `video: false`、`video_required: false`、`required_modules: ["core", "bridge"]`、`optional_modules: []`。

管理服务示例为 `/home/fire/ros2_ws_car/src/robot_manager/config/manager.example.json`。以上路径是正式部署示例，当前本机没有因此自动创建 `/etc/robot24` 或 `/opt/robot24` 的部署。

### 3. 下位机日常实机启动

先确认机器人供电、接线、现场作业范围及实体急停状态。CAN 配置只在尚未运行整车软件时进行，因为配置脚本会先关闭再重新打开接口。

核对接口及波特率：

```bash
ip -details link show canable0
ip -details link show canable1
```

确认现场使用这两个接口且波特率确为 **1 Mbit/s** 时，可使用现有辅助脚本：

```bash
bash /home/fire/ros2_ws_car/src/robot_bringup/scripts/bringup_can_interfaces.sh
```

该脚本可能要求 sudo；波特率不同应按已核验的现场配置设置，不直接套用默认值。

若已按 README 部署 systemd 服务：

```bash
sudo systemctl start robot24-manager
systemctl status robot24-manager --no-pager
```

若使用手动前台运行，则在下位机执行以下命令并保持终端打开；**它与 systemd 二选一**：

```bash
python3 -B /home/fire/ros2_ws_car/src/robot_manager/manager.py \
  --config /etc/robot24/manager.json
```

这里沿用源码管理器路径；如果管理器已部署到 `/opt/robot24/manager`，将脚本路径换成该部署目录。管理器会自行 source 配置里的 `setup`。

可执行只读部署检查：

```bash
python3 -B /home/fire/ros2_ws_car/src/robot_manager/deployment_check.py \
  --config /etc/robot24/manager.json --probe
```

部署检查通过后，仍须在上位机对选定 hardware 档案执行“检查连接与环境”。

### 4. 上位机连接真实下位机

1. 在上位机电脑打开程序。本机仍可运行 `bash /home/fire/hostcomputer/scripts/run_linked.sh`；其他电脑使用部署好的上位机程序。
2. 打开“一键启动 → 连接设置”，将预填的 `127.0.0.1` 改成**真实下位机 IP**，管理端口为 `9091`，令牌改为该下位机部署的认证令牌。不能把 `0.0.0.0` 当作连接地址。
3. 点击“连接”，选择服务实际提供的 `hardware/实机` 环境，检查预检结果，再选择所需运动组。
4. 归中后点击“一键启动”。该操作会启动实机软件，并对所选运动组执行初始化、使能、运行流程；实车在获得遥控授权后能够响应输入。
5. 确认所选组“运行中”、运行许可有效后，再进行低速、小幅控制。遥控暂停时重新归中并明确点击“允许遥控”。

上位机通过 TCP 连接下位机，不要求上位机安装 ROS2。`9091` 是管理端口，`9090` 是控制端口，两者不要填反。若本机模拟管理器也在运行，注意核对连接的 IP 和运行环境，避免连错对象。

## 三、怎样控制运动组

只勾选需要操作的组；勾选只是待启动选择，已经运行的其他组不会因为取消勾选自动停止。要关闭原来运行的组，应明确停止对应组。

当前整车入口默认采用独立分组 v2 策略：只初始化、使能、运行所选组，未选组未启动、停止或普通轴故障不直接阻止当前组，也不会因未选组状态变化撤销遥控授权。机械臂预设包含夹爪。全局急停、当前组所使用的共享资源故障，以及现场明确配置的物理联锁仍有效；配置的联锁证据缺失或过期不能绕过。显式使用旧 v1 策略的启动方式仍按原规则运行。

具体变更见 `/home/fire/hostcomputer/docs/运动组独立运行实施说明.md`。基础 ROS 软件仍统一加载，单组运行不表示可以删除其他组的软件包。

此前为模拟启动临时增加的自动安全条件注入已经删除，当前使用独立分组策略。本机 mock 档案为 revision 4；不要重新添加旧 `mock_safe_posture` 字段，旧字段会被管理服务明确拒绝。

默认键盘映射如下，须先选对控制模式并获得遥控授权；最终以连接设备返回的映射为准：

| 控制模式/对象 | 按键 |
| --- | --- |
| 底盘模式：前进/后退 | W / S |
| 底盘模式：左转/右转 | A / D |
| 底盘模式：左前、右前、左后、右后摆臂正/反方向 | Y/H、U/J、I/K、O/L |
| 机械臂模式：末端 X、Y、Z 正/反方向 | U/O、A/D、W/S |
| 机械臂模式：绕 X、Y、Z 正/反方向 | Q/E、K/I、J/L |
| 机械臂模式：夹爪开/关 | F / H |
| 软件急停 | 空格，或界面急停按钮 |

底盘控制使用“底盘”模式；机械臂末端遥控使用“机械臂”模式并等待实际模式切换成功。切换、换档或断线后可能撤销授权，需重新归中再允许遥控。换档在“一键启动 → 更多控制”中操作，确认实际档位后再控制。

## 四、急停、恢复和正常关机

### 急停后恢复

先处理急停原因并确认实体设备状态，再释放按键、手柄归中。软件恢复步骤：

1. 若提示“上次运行未正常结束”，先点击“停止系统”，等待受控恢复完成，再重新启动软件。
2. 若提示“上次急停仍然锁存”，在软件及控制桥连接就绪后，点击“处理急停”。
3. 依次点击“1. 解除急停锁存”“2. 允许恢复操作”“3. 复位全局禁止”，按提示确认并等待完成。
4. 若所选组仍为 Fault，在“更多控制”中执行“恢复所选组”；完成后再点击“一键启动”，重新获得遥控授权。

按钮不可用时查具体状态，不反复提交。停止系统、重启窗口不会清除急停；不要删除 `state/control` 文件绕过锁存或未知操作。软件显示停止不等于已经确认实车机械停止。

### 正常停止

1. 松开所有运动输入，点击“停止所选组”；需要停止全部运行组时，在“更多控制”点击“停止全部运动组”。
2. 点击“停止系统”，等待管理服务确认已停止。该操作负责停止受管软件。
3. 再关闭上位机。需要关闭下位机管理服务时，在已确认受管系统停止后，再关闭前台管理终端或执行 `sudo systemctl stop robot24-manager`。

不要用关闭终端、强杀进程或 `systemctl stop robot24-manager` 代替“停止系统”。

## 五、常见情况和日志

| 现象 | 优先检查 |
| --- | --- |
| 连接失败 | 管理器是否监听、真实下位机 IP、9091、令牌；跨机器时的监听地址和网络 |
| 环境列表只有模拟 | 下位机尚未部署 hardware 档案，不能直接控制真实电机 |
| 软件就绪但组未运行 | 是否选组、是否完成一键启动、是否归中、是否有急停或关联阻止 |
| 未选组显示“未启动” | 正常，不表示当前组故障 |
| `OWNER_BUSY` | 另一个上位机控制端占用，先关闭旧控制连接 |
| 预检提示端口占用 | 是否手动重复启动了整车或桥接；先对账进程，不盲目杀进程 |
| 包找不到/清单不匹配 | manager.setup、完整安装产物及构建版本；不要 source 旧的不完整 install |
| 断线或换档后不响应 | 重新同步、释放输入、归中，再显式允许遥控 |

上位机运行详情：`~/.local/share/hostcomputer/logs/runtime/runtime.jsonl`、`latest.json`。

本机下位机日志：`/home/fire/ros2_ws_car/linked-runtime/state/` 中的进程日志、`linked-runtime/ros-logs/`；正式部署使用 manager 配置的 `state_dir`，systemd 管理日志可用 `journalctl -u robot24-manager -n 100 --no-pager` 查看。

视频不是基础运动控制的必需条件。需要视频时另行配置真实源、RTSP 公布地址及端口；当前本机模拟档案没有启用视频。
