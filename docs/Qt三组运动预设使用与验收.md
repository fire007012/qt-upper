# Qt 三组运动预设使用与验收

日期：2026-11-12。上位机构建：`host-ros2-v2-presets-2`。接口依据：[文档51](51_三组预设与上位机对接提示词.md)。本次只修改上位机与独立协议测试，没有修改下位机参考代码。

## 使用

1. 打开工具栏“运行管理 / 启动系统”，连接管理服务，选择 hardware/mock 软件档案。软件档案、视频和运动预设相互独立；所有运动预设共用这一次软件启动。
2. 勾选摆臂、底盘、机械臂（含夹爪）。支持七种非空组合，“全车”即三个全选。勾选只编辑待提交选择，不改变机器人确认的选择，也不使能电机。全不选时禁用启动和授权；急停仍始终可用。
3. 冷启动点击“启动系统及所选预设”。管理端软件成功就绪后连接控制桥，只有声明 `motion_presets_v1` 并完成协商才继续。已有软件就绪时使用“启动所选运动组并授权”。旧桥接会明确提示能力不足，不会自动整车启动。
4. 释放所有按键并将摇杆归中，先清除桥接急停。该启动操作明确申请按组执行 `init → enable → resume`，每步等待任务终态、新鲜组状态、最新 epoch/token 和新的中立输入/操作授权；最后在组合许可成立时申请遥控授权。已经 Running 的组跳过初始化和使能。Fault 要由操作员显式 recover，之后再显式启动；不自动清急停或恢复故障。
5. 面板分别显示机器人确认的选择、实际组状态、许可、反馈是否新鲜和流程进度；详细区保留每组 blockers/ready/底层许可状态及操作结果。arm 与 gripper 分别列出，状态不同或一个失败时需逐组核对。结果中的 message 若是 JSON 额外展示解析内容，原文仍保留。外层控制 operation_id 与结果条目内 runtime operation_id 分开保留。

## 增加、取消及停止

- 扩大组合：勾选新增预设，点击“启动所选运动组并授权”。先提交新选择，撤销旧输入和两类授权，再只启动需要改变状态的组。原有 Running 组不会重启。
- 缩小组合：取消勾选后点击同一启动按钮，流程先 halt 被移除预设，等其全部底层组达到 Stopped/Halted 且停止诊断新鲜，再提交新组合，最后重新授权。机械臂的 arm/gripper 必须同时满足条件。也可先勾选要停止的已选预设，点“停止所选组”，再调整勾选并“仅提交选择”。
- “仅提交选择”不初始化、使能或运行；取消仍受新鲜停止状态和底层诊断约束。选择成功后旧 epoch/token/授权作废，新的 token 由 freshness_request 取得。
- 故障时勾选需要恢复的已确认预设，归中并点状态栏“允许操作”，再点“恢复所选组到 Armed”；恢复任务终态和实际组状态在详情区展示。之后仍需显式启动，不自动 resume。
- “停止全部已确认组”按机器人确认的组合停止，与本地待提交勾选无关；全不选时仍可用。“停止所选组”使用 halt，不表示设备断电。全局急停仍通过独立急停通道停止全车，不携带预设子集。停止/急停/断开后不自动重启。
- 组合操作不是原子事务。失败会暂停流程，不自动回滚健康组；结果未知禁止自动重发。到“控制与遥测诊断”核对原操作，已知 operation_id 只查询；丢失接受响应时显式恢复会使用原 request_id 和原 presets 参数。新操作生成新 ID，不能用改变后的勾选替换原请求参数。
- vehicle/arm 是输入映射模式，预设决定运动范围。上位机按已确认选择过滤输入、禁用未选 arm 的模式和命名目标入口。机械臂遥控仍要求部署档案 `enable_servo=true`，且显式切换 arm 模式成功；此项由部署管理员离线配置和受控重启，不能在在线配置维护里修改。

混合的 arm/gripper 状态不会继续批量 init/enable；流程显示需要核对，保留成功组与失败组详情。普通“允许操作”和生命周期按钮仍可用于显式处理已确认选择；不要从勾选状态推断电机已经停止。

## 离线验证与边界

新增 `motion_presets_protocol` 使用生产 ControlSession 和独立 JSON 协议 peer，不加载 ROS 或下位机实现，不创建控制器/总线主站。覆盖七种组合、增量启动、移除前停止、arm/gripper 部分失败、invalidated 成功后的状态同步、结果未知/原ID恢复、未选组输入过滤、运行反馈过期、未选组 Fault、监控不改选择、选择变更后的旧授权/旧状态响应隔离、非法参数和急停中止启动。套接字测试补充首次握手协商、旧服务端不自动启动和急停无预设子集；offscreen widget 回归补充多选/空选择/能力门槛。

```sh
cmake -S tests/communication -B /tmp/hostcomputer-communication-tests -DHOST_BUILD_WIDGET_TESTS=ON
cmake --build /tmp/hostcomputer-communication-tests -j4
QT_QPA_PLATFORM=offscreen ctest --test-dir /tmp/hostcomputer-communication-tests --output-on-failure
```

本机 Qt6.12 需要使用 `/home/fire/Qt/Tools/CMake/bin/cmake`，配置时添加 `-DCMAKE_PREFIX_PATH=/home/fire/Qt/6.12.0/gcc_64`。套接字回归需要本机回环端口监听权限。纯协议组可单独运行 `/tmp/hostcomputer-communication-tests/motion_presets_test`，不需要监听权限。

本轮验证只证明上位机与独立 mock 的行为，以及 Qt6 编译/离屏界面回归。真实上下位机 Qt 联调、真实运行许可与安全关联证据、Servo 部署、物理急停/断网归零和实机一键启动验收仍需单独登记，不能由本次结果替代。

首次接入（`presets-1`）本地结果：Qt 6.12.0 完整应用在 `/tmp/hostcomputer-presets-app` 构建通过；含 Widgets 的通信 CTest 全部 8 组通过（79.16 秒）。最后补充状态同步、恢复/停止入口及空选择保护后，受影响的会话、传输、预设、控件 4 组再次通过（2.59 秒），完整应用重新构建通过。以上均为离线证据，不是机器人端或实机验收。


## 整体复核后的修复（presets-2）

按复核序号修复 1、3、4、5、6、7、8、9。第 2 项按用户要求保留：手柄断开/重新接入不额外撤销已有遥控授权；键盘、窗口失焦、TCP 失联和急停的原保护不变。增加对应行为回归，避免无意改变这一选择。

- 启动期间，“停止所选组”及“停止全部已确认组”保持可用。停止会取消尚未发送的 init/enable/resume，已受理操作仍需等其终态，再依据其后的新鲜状态执行 halt。普通停止不是取消底层 RPC，也不替代始终覆盖全车的急停。
- 管理启动后的自动运动流程只接受本次请求档案和 revision 所发现的机器人、控制地址及新连接；其他机器人、同机器人其他端口、原有连接和软件未就绪时的 Ready 均不会触发。
- 等待能力声明最多 2.5 秒，再发送控制握手，满足服务端三秒握手时限；不再因 200ms 未收到声明而使用整车会话。能力缺失时不取得控制会话；已声明控制 v2 但没有可选预设能力的服务端仍禁用分组操作。
- 停止成功、移除预设及解除未知阻断共用停止证据：每个底层组软件状态为 Stopped/Halted、反馈新鲜、诊断许可状态为停止或 Fault。arm/gripper 分别检查；诊断缺失、仍 Running 或反馈过期均不宣布停止成功。
- 未连接、等待能力声明、正在协商、能力超时/无效、确实缺少预设能力分别提示，不再把未连接解释为需要升级桥接。
- 五个视觉监测按钮禁用并显示当前协议未提供接口；调用被拒绝时显示原因，不再记录虚假的“已请求”。视频查看保留。实际检测功能仍需[下位机接口契约](视觉监测管理接口要求.md)，本次没有扩展或修改下位机代码。
- 独立通信测试恢复 Qt5 兼容，包括可选 Widgets 回归；完整应用仍使用 Qt6，未增加 Qt5 完整 GUI 支持声明。

### 解除结果未知造成的本地阻断

1. 保持原 request_id/operation_id，不换 ID 自动重发 init/enable/resume。先查询/恢复原请求。若接受响应丢失且尚无 operation_id，原 ID 恢复可能执行原操作，必须核对现有确认提示。
2. 停止该历史操作涉及的全部底层组，并等待新鲜停止状态和诊断；旧记录无预设范围时要求全车四组停止。存在在途任务、未完成停止流程、过期/未知诊断时不能确认。
3. 在“控制与遥测诊断”选中原操作，查询后等待新的状态响应，点击“确认停止状态并解除未知阻断”，阅读并确认提示。
4. 仅解除本地后续操作阻断。原操作仍保留 result_unknown，记录操作员确认时间、epoch 和停止证据；不会改成 succeeded，不重发原操作，不恢复运动。之后重新获取 token、中立输入和显式授权，再提交新的操作。记录持久保存；若再次查询发现原结果发生变化，将重新阻断并要求核对。

修复批次验证结果：Qt6.12 完整应用构建通过；Qt6 与 Qt5.15.3 独立通信/可选控件回归分别 8/8 通过。最终相关 Qt6 4组复核通过，Qt5最终预设协议组通过。预设协议组31项（含初始化/清理）通过；不代表 Qt5 完整应用或实机验收通过。
