# 运动组独立运行实施说明

2026-11-14。上下位机共同调整。默认只初始化、使能和启动所选运动组；机械臂预设仍包含机械臂和夹爪。

## 实现规则

新的整车入口默认使用 `robot_safety/config/group_policy_v2.yaml`：

- 未选组的 Stopped、未初始化、未使能、普通轴故障，不再派生为当前组的阻止条件。
- 普通轴故障只停止所属组；共享后端故障影响实际使用该后端的组。例如底盘使用 CanDriverSystem，不因 RobotCanopenSystem 故障自动停机；CanDriverSystem 故障仍会影响底盘。
- 物理联锁直接检查对应目标组的证据，不从源组的软件状态推断，也不沿“夹爪→机械臂→底盘”链式扩散。
- 全局急停、运行协调器的全局所有权失效继续约束全部组。恢复仍需明确操作，不恢复旧运动命令。

v2 默认档案没有未经现场登记的机械关联，也不注入模拟安全证据。旧的 `group_policy_v1.yaml` 及其保守规则保留；显式使用旧策略的启动方式仍维持原行为。已有实车若另有已核验的物理联锁，需要迁移到 v2 的显式规则，不能把该默认文件当作现场联锁清单。

## 明确存在的物理联锁

现场部署可在完整 v2 策略中添加实际需要的规则，例如：

```yaml
associations:
  - source_group: arm
    category: physical_interlock
    dependent_group: base
    condition: arm_secured
    source: commissioned_arm_pose_and_brake
    unknown: block
conditions:
  arm_secured: {initial: unknown, field_evidence: commissioned}
```

配置后，底盘必须取得指定来源、未过期且满足条件的真实证据才能运行；缺失、未知、不满足或过期都会阻止底盘。机械臂是否初始化、使能或有普通软件故障不再替代该证据。恢复证据后仍须重新明确启动；旧授权不复活。上述示例声明规则，不会创建真实传感器或证明安全。

## 管理预检、健康检查与控制授权

上位机的预检和软件启动请求增加可选参数 `presets`，从当前选择传给下位机。下位机验证并将它保存在本次运行状态，不改写磁盘运行档案。

- 底盘只检查底盘所需控制器及 CanDriverSystem，不要求机械臂 action、摆臂或夹爪控制器就绪。
- 机械臂预设检查机械臂、夹爪及它们使用的两个后端；摆臂检查其自身控制器和 RobotCanopenSystem。
- 硬件档案通过 `group_devices` 明确各组使用的设备，再按请求选择预检。硬件示例已补齐默认 CAN 映射；实际设备名不同须同步修改映射。
- 旧档案没有 `group_devices` 时仍检查全部 `devices`，不猜测现场设备归属。旧客户端不传 `presets` 时保留整车检查。
- 基础 ROS 软件栈仍统一加载，单组启动没有拆成多个 controller_manager；加载软件不等于初始化或使能其他组。共享软件进程退出等公共资源故障仍需处理。
- 控制桥现在按所选组过滤状态/epoch 变化。未选组变化不会撤销当前遥控授权；所选组故障会暂停输入，但不额外发送整车 halt，把故障扩散到健康组。全局事件、输入 watchdog、断线及急停的停止流程保留。

一个遥控会话同时选择多个组时，仍要求这次组合的许可完整；组合中某组故障会暂停该会话输入，但健康组不被额外 halt。可改选健康组、归中并明确重新授权后继续控制。这次没有引入多个组各自独立的遥控授权会话。

命令行预检也可选择组：

```bash
python3 /home/fire/ros2_ws_car/src/robot_manager/client.py \
  --token-file /home/fire/ros2_ws_car/linked-runtime/manager.token \
  preflight --profile mock --revision 4 --presets base
```

实际 revision 以服务返回的档案版本为准。当前运行中的软件若要切换到另一组，可在上位机选择并启动该组；新组的设备准备和许可由自身初始化、使能及 C++ guard 再检查。重新进行冷启动设备预检须先停止系统。取消勾选不会自动停止已经运行的组。

实际 Qt → 管理服务/控制桥 → 已安装 ROS → MockSystem 联动单独记录在 `/tmp/group-independent-*`。模拟联动结果不代表实车机械验收；测试没有接入真实 CAN。

- 底盘单组运行，向未选的 wrist_pitch_joint、left_gripper_finger_joint 注入故障，底盘授权与 epoch 不变，并持续运动 15 秒；输出 `/tmp/group-independent-base-fault-v2/summary.json`。

## 删除临时安全注入

已移除 MockSystem 读取临时参数并在启动时断言安全证据的代码，删除两份 URDF Xacro、硬件/整车 launch、manager 启动命令中的参数传递，删除示例、配置生成器、当前本机档案和上位机联调脚本中的字段。旧档案若仍包含该字段，无论 true/false 都明确报 CONFIG，要求删除字段，避免误以为旧补丁仍有效。

保留的 `/mock/conditions/*` 是显式联锁测试夹具：只有策略明确配置了相应联锁、且测试主动调用服务后才提供测试证据；默认 v2 策略不创建这些条件服务，启动不会自动提供任何安全证据。真实物理联锁、全局急停及其恢复门槛没有删除。

删除后的验证：2 个受影响 ROS 包重编译安装，硬件 3 项 CTest、管理服务 34 项测试、配置生成器 2 项测试通过；安装后的 Xacro 已无临时参数。实际模拟联动包含初始急停解除、底盘启动、未选机械臂/夹爪轴故障、15 秒持续运动、再次急停及恢复、停止清理，复测通过，资源为零，记录为 `/tmp/remove-safety-injection-verify/summary.json`。

本轮首次持续运行测试出现一次遥控授权失效（`/tmp/remove-safety-injection-final/qt-probe.log`），相同条件复测未复现，原因尚未确认。已增加失败时的脱敏诊断输出；未放宽任何授权、时效或急停门槛。该波动与临时参数移除的因果关系尚无证据，不能据此宣称已经修复所有偶发暂停。
