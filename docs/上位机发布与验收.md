# 上位机发布与验收

构建 `host-ros2-v2-config-2`，控制v2、管理v1、配置事务v1，匹配参考系列 `robot24-p0-config-2`。本说明覆盖上位机可重复执行的发布和验证；现场总体验收尚未完成。

本轮以Linux x86_64为交付和验收目标。Windows仅保留为可选平台，不阻塞本轮Linux交付。

## 构建与自动回归

完整应用要求 Qt6，包含 Quick/QML/QuickWidgets/Quick3D/OpenGL 模块；纯通信回归仍支持 Qt5。应用不再尝试无法完整链接的 Qt5 回退。发布工具使用 Qt6.12 的原生部署 API，CMake 需满足所选 Qt 的要求。

```sh
CMAKE_BIN=/home/fire/Qt/Tools/CMake/bin/cmake \
CMAKE_PREFIX_PATH=/home/fire/Qt/6.12.0/gcc_64 \
HOST_BUILD_WIDGET_TESTS=ON bash scripts/run_all_tests.sh
```

统一入口包含完整编译、七组 CTest、独立协议冒烟及 Python 发布工具边界/配置迁移测试。回环测试必须允许本机 TCP 监听。禁止把监听被沙箱拒绝当作测试通过。

Linux视频回归可额外设置 `HOST_BUILD_VIDEO_TESTS=ON RUN_RTSP_TESTS=1`，构建目录默认 `/tmp/hostcomputer-video-tests`（可用VIDEO_BUILD_DIR覆盖）。真实RTSP测试使用本机GStreamer RTSPServer、videotestsrc、x264enc、rtph264pay和FFmpeg，不使用相机；依赖缺失会失败，不跳过后宣称通过。

## 生成运行包

```sh
python3 -B scripts/package_host.py \
  --cmake /home/fire/Qt/Tools/CMake/bin/cmake \
  --qt-prefix /home/fire/Qt/6.12.0/gcc_64 \
  --build-dir /tmp/host-release-build \
  --output-dir /tmp/host-release-candidate \
  --ffmpeg /usr/bin/ffmpeg \
  --ffmpeg-license /usr/share/doc/ffmpeg/copyright
```

输出目录和同名 ZIP 必须不存在；构建及发布目录必须互不包含，并位于源码目录之外。工具在启动 CMake 前解析符号链接并验证路径，不清理或覆盖已有发布证据。失败保留 package.log，使用新的输出目录重试。

工具按顺序完成 Release 编译、CMake 安装、Qt/QML 导入及动态插件依赖收集、FFmpeg及其声明文件收集、版本/动态库检查、无开发路径覆盖的平台插件及 QML 对象创建检查，并搬移副本复查本地重定位（Linux另核对Qt动态库来自搬移后的包）。最后生成包含 SHA256、源码提交/未提交标记、兼容声明和验收范围的 release-manifest.json，并压缩成 ZIP。Qt 运行库不复制整个 SDK；FFmpeg 运行还依赖所选构建的系统库，须在目标系统验证。

可用 `--evidence 名称=/tmp/结果.json` 重复指定已选定的JSON验证证据，随包放入validation目录并计算摘要；它不自动把任意外部报告提升为实机或干净机器验收。

Linux 布局为 `bin/hostcomputer`、`bin/ffmpeg`、`lib/`、`plugins/`、`qml/`、`licenses/ffmpeg/`、`docs/`，可执行文件 RUNPATH 使用相对目录。Windows 可执行文件和 FFmpeg 位于包根目录，Qt 部署工具收集 DLL/插件。若工程提供 vendored SDL3，还安装相应共享库。

Windows 使用匹配编译器的 Qt6.12，在对应开发者终端运行同一个 Python 脚本，替换 Qt/CMake/FFmpeg/声明文件路径。当前 Linux 环境没有 Windows Qt 工具链，Windows 编译、XInput/SDL、平台插件及视频实际播放仍未验收，不能因脚本跨平台就改为已通过。

独立检查已安装包：

```sh
python3 -B scripts/check_host_runtime.py --app-dir /tmp/host-release-candidate/bin --require-bundled-ffmpeg
QT_QPA_PLATFORM=offscreen /tmp/host-release-candidate/bin/hostcomputer --check-ui-runtime
python3 -B scripts/check_host_release.py --binary /tmp/host-release-candidate/bin/hostcomputer --output /tmp/host-release-local.json
```

`--check-ui-runtime` 不创建操作主窗口或连接机器人，仅检查平台插件加载和实际 RobotView.qml 对象创建。offscreen 通过不能证明显卡渲染、视频、手柄、桌面交互或干净机器运行。包内明确保留这些未验收标记。完整再分发还应随所选 Qt/FFmpeg/SDL 构建提供对应声明、来源及必要材料；本机安装检查不替代目标系统的依赖与分发检查。

本机图形环境可单独执行 `hostcomputer --check-render-runtime`。它短暂显示独立RobotView窗口，要求至少两帧并进行非软件SceneGraph的图像读回；输出平台、图形API和渲染结果，不创建操作页或连接机器人。Wayland本机通过仍不代表另一台Linux机器或实体GPU性能已验收。

`hostcomputer --smoke-ui-runtime` 创建完整主窗口，运行约3秒后正常析构并退出；测试时将XDG_CONFIG_HOME指向源码外的空目录。此项只验证窗口生命周期，不操作连接、授权或设备。Linux包同时收集X11/Wayland及离屏平台插件。

## 本机 ROS2 仿真联调

已核对环境为Ubuntu22.04.5/ROS2 Humble，未发现CAN接口、串口和相机设备。Qt本身仍不需要ROS。本测试显式只读加载给定桥接源码，使用真实RosOutput和DDS，由独立mock发布运行许可、接收Twist及提供Trigger服务；不会连接硬件。

本机缺少robot_hardware/arm_control自定义类型时，可仅从接口原定义生成临时测试覆盖层：

```sh
python3 -B scripts/prepare_ros2_mock_interfaces.py \
  --reference-src ros2_ws_car/src --output-dir /tmp/host-ros2-interface-fixture
source /tmp/host-ros2-interface-fixture/install/setup.bash
python3 -B tests/communication/ros2_reference_integration.py \
  --bridge ros2_ws_car/src/host_bridge/host_bridge_node.py \
  --probe /tmp/hostcomputer-communication-tests/control_reference_probe \
  --output-dir /tmp/host-ros2-contract
```

类型定义逐字节复制并记录SHA256；临时包仅包含SetProfile和ExecuteArmGoal，不是完整robot_hardware/arm_control安装，不得用作机器人部署包。所有源、构建、安装、ROS日志及journal都在/tmp。runner在导入ROS前固定localhost隔离和测试domain196（可显式指定101..200），测试Qt显式授权、ROS模拟运动、异步init、独立急停期间真实ROS零命令和halt、迟到完成invalidated及保持撤权。没有实机CAN或设备归零验收。

管理20轮无设备契约另行执行：

```sh
python3 -B tests/communication/manager_reference_integration.py \
  --manager ros2_ws_car/src/robot_manager/manager.py \
  --probe /tmp/hostcomputer-communication-tests/manager_reference_probe --cycles 20
```

该项使用真实管理协议与Qt RuntimeService、注入后端，不启动ROS/进程，不等于systemd冷启动20轮。

## 配置迁移差异

工具只读取管理 JSON 档案或 `config.source` 导出结果；不会解析并合并 ROS1 YAML，不迁移未经契约定义的电机参数：

```sh
python3 -B scripts/profile_migration_report.py \
  --previous /tmp/old-profile.json --current /tmp/current-config-source.json \
  --output /tmp/profile-migration.json
```

必须显式匹配 profile_id。报告列出当前源 revision、两项可编辑策略的建议补丁、缺失/非法字段及未映射差异；缺失值不补默认。存在未解决差异时退出码为1，但仍保存报告；参数/输入错误为2。不创建候选、不应用、不写设备。随后在 Qt 配置维护页重新读取服务器 schema/revision，人工核对差异并走现有候选/停机/应用/读回流程。ROS1 设备参数转换需下位机提供来源映射与新 schema。
