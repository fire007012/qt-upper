# 上位机 ROS2 适配与可靠性重构计划

更新：2026-11-17。本页保留 `AGENTS.md` 所引用的职责与实施顺序；旧长篇设计和分批实施记录已移至 [开发归档](开发归档/README.md)。当前使用说明以 [文档入口](README.md) 为准。

## 工作边界

`ros2_ws_car/` 是下位机代码的只读参考副本，禁止修改、新增、删除、移动、格式化，也禁止通过构建、测试、生成脚本、字节码或日志在其中写入产物。下位机桥接、ROS2、管理服务、CAN 与系统部署由下位机开发端在独立授权工作区实施；本仓库只实现上位机和独立 mock。

上位机通过 TCP/JSON 与既有服务通信，不直接引入 ROS/DDS，也不通过 SSH 或任意 shell 修改车辆。上位机保存偏好和操作恢复记录，机器人源配置及运行许可仍以下位机为权威。

## 当前基线

- 上位机 `host-ros2-v2-field-1`，完整应用使用 Qt6，本机 Qt6.12.0；Linux x86_64 为本轮目标，Windows 为后续可选项。
- 管理 v1、控制 v2、配置事务 v1 已接入；分组预设、换档、独立急停与分步恢复按能力开放。
- 配置维护只编辑启动超时和视频必需策略，不支持电机参数和 CAN 名称写入。
- 独立回归与历史安装栈模拟有记录；当前车辆实机验收仍未完成。历史 `/tmp` 路径不保证长期可用。
- 现场仅接底盘，接口要求为 `can0`；车辆实机档案、设备映射和急停根因仍需下位机配置及联调确认。

详细能力及验收范围见 [兼容声明](../deploy/compatibility.json)。不以 mock 通过、TCP 连通、软件 ready 或急停回执代替硬件输出证据。

## 后续顺序与责任

| 顺序 | 工作 | 责任及完成依据 |
| --- | --- | --- |
| 1 | 固定现场基线 | 双方登记 IP、启动命令、Qt/管理/桥接构建、档案与 revision、选组、实际 CAN 名称、故障日志；不预设唯一根因 |
| 2 | 先完成底盘实机配置 | 下位机部署端核对 hardware 档案、`can0` 映射、设备身份、方向、波特率、基线及受管进程；上位机仅选底盘并预检 |
| 3 | 控制与急停联调 | 双方验证真实许可、初始锁存、停止清理、显式解除/复位、初始化及低速控制；保留物理停止和输出归零证据 |
| 4 | 可靠性及部署 | 验证断网/半开/重启、积压输入、旧会话、时钟跳变、多客户端、慢任务隔离；下位机验证管理自启、冷启动和受控清理 |
| 5 | 扩展接口 | 先冻结设备参数和视觉监测契约及 fixture，再实现上位机入口；不凭 mock 字段宣布已交付 |
| 6 | Linux 发布 | 按当前发布工具打包，在干净目标机验证 Qt/QML/视频/输入、安装和回退，再签收现场一键启动 |

设备参数和视觉检测的待办分别见 [设备接口要求](下位机设备参数维护接口要求.md)、[视觉接口要求](视觉监测管理接口要求.md)。测试命令见 [通信测试](../tests/communication/README.md)，签收证据见 [发布与验收](上位机发布与验收.md)。

按既有用户调整，24 小时持续运行验证已取消，不作为本轮出口；短时故障恢复、时钟跳变、队列边界和授权失效测试继续保留。Windows 未验证，不影响本轮 Linux 目标，但也不声明已兼容。
