# Qt 运行管理与构建

更新：2026-11-20。管理协议 v1，默认 TCP `9091`；控制使用独立 v2 连接。运行配置为 `~/robot24-portable/runtime/manager.json`，下位机入口为 `bash ~/robot24-portable/run_manager.sh`；旧 linked-* 目录和兼容入口已移除。日常入口见 [启动与控制](上下位机启动与控制说明.md)，接口依据为下位机 [管理协议39](../ros2_ws_car/src/docs/archive/qt/39_下位机管理协议与Qt对接.md)。

## 连接与启停

工具栏“系统管理 → 一键启动”打开启动页。连接前即可在“准备启动的环境”选择 `mock / 模拟` 或 `hardware / 实机`；首次使用不默认选择，后续记住操作者的选择。“连接设置”包含管理地址、端口、令牌、匹配所选环境的部署档案和运动预设，以及“参数维护”页。令牌至少 32 字符，仅保留在内存；地址、端口与按管理端点及环境隔离的档案选择会保存。

连接自动完成 hello、能力、profiles、snapshot 和当前 operation 查询。档案及 revision 来自服务端，只匹配操作者提前选定的环境；没有对应档案时保留选择并禁止启动，不自动改选另一种环境。多个匹配档案需在连接设置中明确选择；原档案失效不回退到列表第一项。软件未启动且无需恢复时，点击“检查连接与环境”。预检结果详情写入运行日志。

“一键启动”在软件未启动时提交 `robot_id/profile_id/config_revision/presets`，由管理服务内部预检并启动软件；在软件已就绪时启动所选运动组。勾选不自动提交、停止或使能。分组流程与急停恢复见 [控制与诊断](Qt控制v2与诊断使用.md)。

管理服务约每秒轮询快照、当前操作和日志。只有任务对账成功、软件 ready/degraded、运行档案 revision 匹配、必需模块健康和端点兼容时，才交付控制地址。端点中的 localhost/回环地址按下位机地址解析。Qt 继续核对机器人身份、控制能力、会话及运行状态。

界面分别显示“当前”运行环境和“准备启动”的目标。若下位机已运行在另一种环境，不连接该环境的控制端点，也不能启动或恢复其运动组；先点击“停止系统”，再检查并启动所选环境。选择本身不会自动启停，普通状态轮询不会禁用环境选择。

“停止系统”撤销本地遥控并关闭当前控制连接，再提交管理 stop。关闭 Qt 或断开管理不发送 stop、不取消已受理任务。管理失联也会关闭本客户端的控制连接；服务端任务继续执行。

## 恢复与维护

重连先查询当前操作和实际快照，不重放 start/stop。本地按管理端点保存请求及操作标记，用于提示结果未知；不把磁盘旧记录当作执行依据。AUTH/VERSION/hello/profiles 错误停止自动重试，修正后显式连接；普通掉线约每 3 秒重连。

`recovery_required` 表示上次运行需要管理恢复，按提示先受控停止并核查。它与桥接急停锁存是不同状态，不能通过清急停替代资源对账。

点击“停止系统”后立即显示停止与资源核对进度；停止期间不会继续用旧的恢复提示覆盖进度。若返回 `STOP_UNCONFIRMED`，启动页显示停止未确认及具体原因（例如运行服务仍在核对归属或停止服务不可用），保留启动阻断。该错误表示下位机没有完成受控停止，不是界面已恢复；需处理下位机运行服务和残留资源后，再显式重试。Qt 不删除状态文件或自动重发停止请求。

配置维护用独立管理连接，仅开放启动超时和视频必需策略，详见 [配置维护](Qt配置维护使用与联调.md)。运行中可以选择下一次启动的目标环境；实际切换需要先停止软件。启停和配置事务执行期间暂时锁定选择。下位机负责最终的 revision、维护前提、资源归属及并发校验。

## 窗口与输入

顶部工具栏可选择键盘/手柄，默认键盘；“返回键盘控制”将焦点移回操作窗口。切换来源或编辑设置后须归中并重新授权。窗口按可用屏幕尺寸打开，右侧控制面板优先显示输入提示；小屏下侧栏、管理页及工作区通过滚动访问完整内容。

## 运行记录

启动页保留简短状态；详细连接、模块、任务、错误、预检和控制事件写入文件。“连接设置”显示实际日志目录。默认使用 Qt `AppLocalDataLocation` 下的 `logs/runtime/`，本机通常为：

```text
~/.local/share/hostcomputer/logs/runtime/runtime.jsonl
~/.local/share/hostcomputer/logs/runtime/latest.json
```

`HOSTCOMPUTER_RUNTIME_LOG_DIR` 可指定其他目录，必须放在只读参考目录之外。

- `runtime.jsonl`：带 UTC 时间的事件，语义不变不重复追加；约 5 MiB 轮转，保留当前文件和 4 份历史文件。
- `latest.json`：每秒原子更新管理/控制状态；关闭窗口时写入 `page_open:false`，不代表此后车辆仍处于相同状态。

文件隐藏令牌、会话信息和 URL 凭据，权限仅当前用户读写。目录不可写时界面提示日志保存失败。诊断页可另行导出控制和遥测观测。

## 本机 Qt6 构建

完整应用要求 Qt6（CMake 中最低 6.5）及 Quick/QML/QuickWidgets/Quick3D/OpenGL；当前使用 Qt6.12.0。该 Qt 要求 CMake ≥ 3.25，本机系统 CMake 3.22.1 不够，使用 Qt 附带版本：

```bash
/home/fire/Qt/Tools/CMake/bin/cmake -S . -B /tmp/hostcomputer-qt6-build \
  -DCMAKE_PREFIX_PATH=/home/fire/Qt/6.12.0/gcc_64 -DCMAKE_BUILD_TYPE=Debug
/home/fire/Qt/Tools/CMake/bin/cmake --build /tmp/hostcomputer-qt6-build -j 4
/tmp/hostcomputer-qt6-build/hostcomputer
```

最后一条在图形桌面运行。offscreen 只验证对象和窗口生命周期，不能替代实际 Quick3D 渲染验收。构建、缓存及测试日志均放参考目录之外。

回归见 [通信测试](../tests/communication/README.md)，运行包和发布检查见 [发布与验收](上位机发布与验收.md)。mock 成功不代表车辆部署、自启、真实输出或现场一键启动已验收。
