# Qt 运行管理使用与联调

日期：2026-11-08。依据：[39_下位机管理协议与Qt对接](../ros2_ws_car/src/docs/39_下位机管理协议与Qt对接.md)。当前交付上位机管理闭环和独立测试，不代表现场一键启动、完整 P0 或配置维护实机已验收。

## 使用入口

1. 打开上位机，点击工具栏“运行管理 / 启动系统”。
2. 填写下位机管理地址、端口（默认 9091）和部署令牌，点击“连接管理服务”。令牌至少 32 字符，仅保留在内存，不写入 QSettings 或客户端日志；每次重新打开应用需重新填写。地址、端口和所选档案会保存。
3. 客户端自动完成 hello、能力核对、档案查询及当前快照/操作查询。档案和 revision 以服务端返回为准。管理未连接或查询未完成时，启动/停止不可用。
4. 在未启动且不需要恢复时，可单独“预检”，查看失败检查项；点击一次“启动系统”即提交带 robot_id/profile_id/config_revision 的请求，服务端在启动任务内部执行预检。Qt 不拼接 SSH 或 launch 命令。
5. 查看操作 ID、accepted/running/succeeded/failed/cancelled 状态、阶段、错误及建议。每约 1 秒查询快照、当前操作及一页日志。必需模块异常不连接桥接，可选模块失败以 degraded 和模块详情显示。
6. 任务核对成功、快照为 ready/degraded、所选部署档案 revision 匹配、所有必需模块健康且控制端点兼容后，自动连接控制桥。端点中的 localhost/回环地址按下位机地址解析。控制桥需通过控制v2机器人身份/session/epoch/六项能力核对，并完成有效心跳及实际控制状态同步。
7. “软件已就绪，待授权”仅代表软件可服务。初始化、使能、恢复、解除急停和允许遥控仍由操作员明确执行；最近中立输入和实时控制状态仍受现有控制链路约束。未知 safety 显示“未知”，不根据软件 ready 补出硬件许可。
8. 点击“停止系统”前客户端会撤销遥控并关闭控制连接，再提交受控 stop；停止失败时查看服务端错误和日志，不认为进程已清理。

“断开管理”或关闭 Qt 不发送 stop，不取消服务端已接受的任务；当前上位机控制连接会关闭并撤销本地遥控。重连先查询原服务的当前操作和快照，不重新提交 start/stop。管理连接异常时当前客户端采取保守策略，同样关闭其控制连接；服务端任务继续独立执行。

QSettings 保存按管理端点划分的 request_id、操作 ID 和未确认请求标记，用于结果未知提示。恢复以服务端当前 operation/snapshot 为准，既不回放磁盘记录，也不自动启动新任务。AUTH/VERSION/hello 或 profiles 错误停止自动尝试，修正后重新连接；普通掉线/超时每约 3 秒重新认证和查询。失败重试是排查后的显式新请求，RECOVERY_REQUIRED 必须先受控 stop/核查。

## 本机 Qt6 构建

本机 Qt 位于 `/home/fire/Qt/6.12.0/gcc_64`，需 CMake 3.25 或更高；系统默认 3.22.1 不满足 Qt6.12 要求。以下使用 Qt 安装附带的新版 CMake，不降低 Qt 要求：

```sh
/home/fire/Qt/Tools/CMake/bin/cmake -S . -B /tmp/hostcomputer-qt6-build \
  -DCMAKE_PREFIX_PATH=/home/fire/Qt/6.12.0/gcc_64 -DCMAKE_BUILD_TYPE=Debug
/home/fire/Qt/Tools/CMake/bin/cmake --build /tmp/hostcomputer-qt6-build -j 4
/tmp/hostcomputer-qt6-build/hostcomputer
```

最后一条在图形桌面终端运行。无显示环境下的 offscreen 启动只能检查进程和 UI 创建，软件 Qt Quick 后端不支持现有 Quick3D 姿态视图，不能作为 3D 渲染或人工界面验收。

独立通信、界面回归与可选下位机契约测试见 [通信测试说明](../tests/communication/README.md)。所有产物在 `/tmp`；不在 `ros2_ws_car/` 构建、写缓存或运行会写入参考目录的工具。
